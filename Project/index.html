01 · What do you need to do?

Group rule: Each group must have 3 or 4 students only (maximum 4). Groups with 2 or 5 students will not be accepted. Every member is assessed individually in Task 4 (3 marks).

Work in a group to create ONE working IoT website or mobile application. You can use real or simulated sensor data. Your application should display data and respond to it, such as switching a virtual fan on when temperature rises.

Build

Working app + sensor data + appropriate action + sensor settings

Document

Maximum 5-page PDF with 3–5 real AI prompts and screenshots

Share

GitHub source code + README + report

Explain

Live demonstration and discussion with every group member

Required development environment: VS Code with Codex or Claude, or Google Antigravity. At least one AI coding assistant must be used. Physical hardware is optional.

04 · Your project journey — step by step

STEP 1

Choose the problem and plan your IoT system

Write one sentence describing the problem. Identify sensor → controller / application → decision → output. Decide which values are simulated and what happens when a condition changes. Select the right sensors and communication protocols for the group based task, or explain clearly when communication is simulated and no real protocol is implemented.

Example: A classroom gets too hot. The temperature sensor provides a reading. The app checks whether it is above 30°C. The virtual fan switches ON when the temperature is above 30°C, otherwise OFF.
STEP 2

Create a project folder and start coding with AI

Open VS Code and use Codex or Claude, or open Google Antigravity. Copy the project prompt from the next section. Ask the AI to create a simple website with HTML, CSS and JavaScript, or a mobile app if you prefer. Review the generated code before running it.

Suggested files for a simple website: index.html, style.css, script.js, README.md.

STEP 3

Build the user interface and sensor simulation

Show the sensor reading with its unit (for example, 25°C or 40% soil moisture). Add a way to change the reading, such as a slider, input box, or automatic update. Explain the sensor type and the value range or threshold in the interface. Demonstrate the basic configuration related to IoT sensors, including the simulation settings.

STEP 4

Add the automatic action

Write a simple rule such as IF temperature > 30°C, fan ON; ELSE fan OFF. The result must change when the sensor value changes. Use clear ON/OFF labels or an alert message.

STEP 5

Test the app and fix problems

Try normal, boundary, and abnormal readings. Verify the correct output for each test. Use AI to help debug, but test the fix yourself. Capture screenshots for the report.

Test caseInputExpected result

STEP 6

Upload to GitHub

Create a repository, upload all working source files, add a README.md explaining the project and how to run it, and include your final PDF report. Test the repository link in a private browser window. GitHub Pages is optional for a static website; the GitHub repository itself is required.

STEP 7

Write your report and prepare your demonstration

Use the report template below, include 3–5 actual AI prompts, screenshots, results, and a conclusion. Each group member should be able to explain the sensor, decision rule, app functionality, AI usage, and their own contribution. The report must present the output result as lab record.

05 · Try a working IoT simulation

This classroom example shows the same logic you can build in your own project. Move the temperature slider and observe the virtual fan.

Smart Classroom · Temperature control

Fan OFF

25°C is not above 30°C, so the fan stays OFF.

Simulated temperature sensor → application checks threshold (30°C) → virtual fan status updates. This is a learning example, not a completed group project.

What should students explain about this simulation?

The input is temperature in °C. The decision rule is temperature > 30. The output is the fan status. At exactly 30°C, the fan remains OFF. Students should show at least three test values and explain why each output is correct.

Prompt B · Improve the interface

Improve the website design using clear labels, readable text, responsive cards, and a sensor status indicator. Keep the code simple and explain each change.

Prompt C · Test the logic

Review my sensor simulation and automatic control logic. Suggest at least three test cases: below threshold, at threshold, and above threshold. Explain expected and actual results and help me fix any errors.

Write a simple README.md for this IoT application. Include project purpose, simulated sensor inputs, decision rule, features, files, how to run the application, and limitations. Do not claim hardware is used if it is simulated.

07 · Four compulsory assessment tasks

Task 1 · Working IoT Application — 6 marks

  1. Run correctly with a working user interface.
  2. Select the right sensors and display simulated or real sensor data.
  3. Apply IoT concepts to solve problems through an appropriate action or control.
  4. Demonstrate the basic configuration related to IoT sensors, including how readings are generated or updated, to accomplish group tasks.

Task 2 · Project Documentation — 4 marks

  1. Project overview: title, objective and operation.
  2. AI assistant used and 3–5 actual prompts.
  3. Write the lab report and present the output result as lab record, including screenshots of sensor readings and system responses.
  4. Conclusion: whether the application achieved its objective.

Task 3 · GitHub Repository — 2 marks

  1. Complete working source code.
  2. README describing the project and how to run it.
  3. Project report in the repository.

Submit the GitHub repository link.

Task 4 · Individual Project Demonstration and Discussion — 3 marks

  1. Demonstrate the working application and basic configuration related to IoT sensors to accomplish group tasks.
  2. Select and explain the right sensors and communication protocols used for the group based task.
  3. Apply IoT concepts and communicate the technical aspects, including AI coding tools, to solve problems.

All 3 or 4 group members participate individually. This task is worth 3 marks.
