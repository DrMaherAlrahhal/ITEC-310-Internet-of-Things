1Why do we need a sensor network?

Last week, we used one sensor to measure a physical condition. But the university garden has different areas. One soil-moisture sensor cannot tell us how wet the soil is everywhere.

So we place three sensors in different areas and connect them to a gateway, which collects their readings.

Key idea: A sensor network is a group of sensing nodes that communicate to collect data from multiple locations.
Now that we have several sensors, a new question appears: How should each sensor send its reading to the gateway? That is a network-topology decision.

2How do sensors communicate?

We can connect sensors in different ways. Explore star and multi-hop networks. Select a sensor to trace its packet.

Trace reading from:
Star topologyEach sensor sends readings directly to the gateway. Simple, but each node needs a reliable direct connection.
Multi-hop topologyA sensor can forward readings through neighbors. This can extend reach, but forwarding uses energy and depends on other nodes.
We can now choose a communication path. But will the connection actually work if a sensor is far away, behind trees, or running on a small battery? This brings us to network design.

3How do we design a good sensor network?

Four factors matter: coverage, energy, reliability, and reporting frequency. We need a balance, not just the longest possible connection.

📍 CoverageCan every required garden location be monitored and connected?
🔋 EnergyDo sensing and radio transmissions drain batteries too quickly?
📡 ReliabilityCan readings arrive despite trees, interference, or failed links?
⏱️ Reporting frequencyHow often should sensors send data? More frequent updates usually mean more traffic and energy use.
