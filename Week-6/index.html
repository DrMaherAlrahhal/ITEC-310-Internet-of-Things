1From Sensors to Smart Objects

Last week: how sensors form networks. This week: how smart objects exchange information with other devices and applications.

A smart object can sense, process, communicate, and sometimes act. Our example is a Smart Classroom Door.

The door sensor detects an event. The ESP32 processes it. But first, how does the sensor connect to the ESP32?

2GPIO – Local Connections

GPIO (General Purpose Input/Output) refers to pins on a controller. An input reads a sensor or button. An output controls an LED, buzzer, or suitable control circuit.

GPIO works locally. But if a teacher wants a notification on a laptop, how can the ESP32 communicate across a network?

3Wi-Fi and BLE – Wireless Communication

Wi-Fi connects the ESP32 to a local network that may provide Internet access. BLE (Bluetooth Low Energy) lets it exchange data with compatible nearby devices using low power.

Now the ESP32 can use Wi-Fi to reach a network. But how does it send its information to the correct application? That is the job of MQTT.

4What Is MQTT?

MQTT (Message Queuing Telemetry Transport) is a lightweight messaging protocol commonly used in IoT. Devices and applications exchange short messages through an MQTT broker.

Wi-Fi = network connectivity. MQTT = how messages are organized and delivered. MQTT can also work on a reachable local IP network without Internet access.

classroom/temperature

32°C

The actual value or command. Examples: 32, OPEN, ON.

8Why Do We Need MQTT?

One ESP32 may need to send the same temperature reading to a laptop, phone, and university dashboard. MQTT makes this easy: publish once to the broker; deliver to matching subscribers.
